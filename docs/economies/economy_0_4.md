# Economy 0.4 — Money and monetary settlement

Economy 0.4 keeps the real exchange economy from Economy 0.3 and adds exactly one new mechanism: **money settles every market trade**.

The agents still optimize over the two real goods, X and Y. Price discovery is still Walrasian tâtonnement. User-added redistribution periods still work as before. The difference appears only after the market has converged: every goods transfer is paired with an explicit money-payment leg in the opposite direction.

## What is new

Each agent now has three balance-sheet stocks:

- X
- Y
- Money

For example, if Agent 2 buys 0.4 units of X from Agent 1 at `pX = 1.20`, Economy 0.4 records one economic trade with two ledger legs:

1. Agent 1 → Agent 2: `0.4 X`
2. Agent 2 → Agent 1: `0.48 Money`

because

```text
payment = quantity × price = 0.4 × 1.20 = 0.48
```

The two ledger legs share the same `trade_id`. Each physical or monetary transfer still has its own globally unique `transaction_id`.

## Prices

Money is the unit of account. Y remains the numeraire:

```text
pY = 1 Money per Y
```

and tâtonnement discovers:

```text
pX = Money per X
```

Because `pY = 1`, the numerical value of `pX` is also the relative price of X in units of Y.

## Money does not change demand yet

This distinction is deliberate.

In Economy 0.4, Cobb-Douglas utility is still

```text
U_i(X, Y) = X^alpha_i Y^(1-alpha_i)
```

and the real budget used for demand is still the market value of the agent's X/Y endowment:

```text
w_i = pX x_i + pY y_i
```

Opening Money is **not** added to this demand budget. Therefore the standard Cobb-Douglas demands remain

```text
X_i* = alpha_i w_i / pX
Y_i* = (1-alpha_i) w_i / pY
```

Changing the amount of opening Money therefore does not change preferences, desired X/Y bundles, or the equilibrium relative price in Economy 0.4.

That is the central teaching point of this version: **money can be introduced as a settlement and accounting object before it is allowed to change real behavior**.

## Monetary settlement rule

Economy 0.4 reuses the proven many-agent clearing allocation from Economy 0.2 inside every Economy 0.3 period.

For every settled goods transfer:

```text
seller → buyer: q units of good g
buyer → seller: q × p_g units of Money
```

The goods and payment legs are generated only after price discovery has converged. There is still no trade during tâtonnement.

The ledger therefore makes the distinction between an **economic trade** and its **accounting legs** explicit:

```text
trade 17
  transaction 33: Agent A → Agent B, 0.25 X
  transaction 34: Agent B → Agent A, 0.25 × pX Money
```

## Batch clearing, not a liquidity constraint

The payment legs are treated as one settlement batch. Economy 0.4 does not ask whether a buyer has enough cash immediately before each individual ledger row is processed.

That means Money is not yet a cash-in-advance constraint and the ordering of payment rows is not economic behavior. The economically meaningful monetary stocks are the opening and closing balance sheets plus the complete set of gross payment instructions.

A later economy can make liquidity matter by requiring agents to fund purchases from available money balances. That is intentionally outside Economy 0.4.

## Stock-flow accounting

For every agent and every asset `A ∈ {X, Y, Money}`:

```text
closing_A = opening_A + net_flow_A
```

The engine checks this identity directly.

It also checks conservation:

```text
sum closing X     = sum opening X
sum closing Y     = sum opening Y
sum closing Money = sum opening Money
```

and

```text
sum net flow X     = 0
sum net flow Y     = 0
sum net flow Money = 0
```

For each individual agent, the monetary flow generated by settlement is the negative market value of that agent's settled real-goods flow:

```text
net Money + pX × net X + pY × net Y = 0
```

This identity follows mechanically because every goods transfer has an equal-value reverse money payment.

## Population size and repeated periods

Economy 0.4 preserves Economy 0.3's mirrored-pair population design and period structure. The app defaults to ten agents, but the user may choose any even population from **2 through 20 agents**. Complete mirrored pairs are always retained, so the untouched baseline remains balanced with analytic `pX = 1`.

Changing the number of agents changes the real economy, so the app resets any existing redistributions and returns to a fresh baseline for the newly selected population. Changing only opening Money, initial trial `pX`, or `lambda` does not reset the redistribution experiment.

The user may add redistribution periods by moving Y between agents. Each period independently:

1. receives its exogenous X/Y opening endowments,
2. starts with the configured opening Money balance per agent,
3. discovers `pX`,
4. settles the real allocation,
5. adds the matching money-payment legs,
6. closes all three stock-flow accounts.

Money is reset to the configured opening amount at the start of each exogenous period. Carrying financial wealth through time would introduce an additional intertemporal mechanism, so it is deferred.

## Canonical configuration

The default app uses:

- the ten-agent Economy 0.2 mirrored population,
- an optional even agent count from 2 through 20,
- one baseline period initially,
- `10.0 Money` opening balance per agent,
- `pY = 1`,
- initial trial `pX = 0.5`,
- adjustment speed `lambda = 1.0`,
- market-clearing tolerance `1e-6`.

The mirrored baseline has an analytic equilibrium `pX = 1` for every supported even population size. The amount of opening Money does not affect that benchmark in Economy 0.4.

## Model boundary

Economy 0.4 includes:

- heterogeneous optimizing agents,
- two real goods,
- a selectable mirrored population of 2–20 agents in the app,
- repeated exogenous redistribution periods,
- Walrasian price discovery,
- explicit money balances,
- monetary prices,
- gross money-payment legs,
- append-only settlement records,
- stock-flow accounting for X, Y, and Money.

It still excludes:

- money in utility,
- a cash-in-advance or liquidity constraint,
- borrowing,
- banks,
- deposits,
- interest,
- money creation or destruction,
- production,
- firms,
- labour,
- government,
- central banking,
- intertemporal saving or inventory carry-over,
- randomness.

The next monetary step can therefore be isolated cleanly: make the available Money stock constrain what an agent can buy, without introducing banking or credit at the same time.
